# 檢查程式與面板修正

本次保留已審核的 SUKKA、DLER 提交與檔案雜湊，只修改檢查程式及自有面板。

## 完整性檢查

- `check` 與 `report` 在固定檔案雜湊不符、缺少固定提交或抓取失敗時回傳失敗狀態，仍產生可審閱報告。
- 每週報告也核對 OWN 與沒有新提交的來源，不會因為沒有上游差異而略過完整性檢查。
- 工作流程在失敗時仍開 issue 附報告，最後保留失敗狀態；不修改 lock、不自動採用上游。

## 面板逐行審核

完整讀過修正後的 `modules/stream-check.js`。只讀取 HTTP 狀態、回應標頭與頁面／JSON 內容；不讀 Cookie、帳號、儲存資料或其他裝置資訊，不使用動態執行、持久化儲存或通知。

請求主機維持：`www.netflix.com`、`www.youtube.com`、`api.openai.com`、`chatgpt.com`、`claude.ai`、`www.tiktok.com`。所有請求只連被檢測服務，`auto-cookie` 維持關閉。Netflix 的手動轉址限 HTTPS 與完全相符的 `www.netflix.com`，避免相似網域。

- ChatGPT 的 HTTP 200 與有效布林欄位 `cookie_consent_required` 才能表示地區檢查通過；明確的 `unsupported_country` 表示地區受限。錯誤、HTML 或不明 JSON 都不能當成功。
- Claude 的 trace 必須是 HTTP 200 且含有效 `loc`。結果只表示出口地區未列為封鎖，不代表帳號或完整服務可用。
- TikTok 任意轉址或沒有地區資訊的頁面改為無法判定。
- 其餘服務保留既有檢測方法；這些無帳號檢查不代替實際播放或登入驗證。

## 驗證

以 Python 標準函式庫測試固定內容遭竄改、OWN 雜湊不符、來源不變、抓取失敗、刪檔及上游差異；以 Node 內建測試模擬 503、逾時、驗證頁、有效地區回應、地區封鎖、相似網域與任意轉址。測試不使用真實帳號或金鑰。

程式提交推送後，再依既有流程更新 OWN 固定提交及雜湊。外部規則固定版本維持不變。
