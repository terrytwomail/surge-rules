# 2026-11-06 App 去廣告腳本審核

擁有者的要求：所有 MitM 腳本，能用的就複製進本倉庫、由本倉庫自己的提交固定，不執行任何別人能改的程式；加密、打包、有問題的不要；真的好用又確認沒問題的才採用。審核原則見 `AGENTS.md` 第 3、5 條。

## 範圍與方法

1. 用 GitHub 的樹狀清單列出 14 個常見腳本倉庫的檔案（app2smile/rules、fmz200/wool_scripts、Maasea/sgmodule、NobyDa/Script、zirawell/R-Store、Keywos/rule、kokoryh/Script、DecoAri/JavaScript、Yuheng0101/X、mieqq/mieqq、xream/scripts、Script-Hub-Org/Script-Hub；RuCu6/QuanX 與 ddgksf2013/Cuttlefish 已不存在），挑出擁有者會用到的 App：國際的 X、Instagram、Facebook、YouTube、Reddit，大陸的哔哩哔哩、知乎（擁有者確認有在用；微博沒在用，不審）。
2. 把候選檔案下載到隔離資料夾，先量：大小、行數、最長一行、有沒有 `eval`／`Function`／`atob`／十六進位跳脫／`_0x` 變數、有沒有 `$httpClient`／`$persistentStore`／`$notification`／Cookie、含哪些網址。最長一行超過幾千字元的就是打包過的程式，直接不採用。
3. 可讀的逐行讀完，列出每個網址分支改了什麼；上游倉庫的授權查清楚；原檔與記錄的上游提交逐位元組核對（SHA-256）。
4. 採用的腳本不是逐字複製，是改寫：只留去廣告的部分，修掉會中途失敗的錯。改了什麼記在 `modules/scripts/NOTICE.md`。改寫後用假的 Surge 環境餵合成回應驗證（13 項），並確認腳本在假環境裡沒有碰網路、儲存、通知。

上游模組（`bilibili.sgmodule`，2026-09-03）：
- `[Rule]` 6 條廣告與追蹤網域（`ad.bilibili.com`、`adcommon.bilibili.com`、`cm.game.bilibili.com`、`track.biligame.bilibili.com`、`adtrack.qianwen.com`、`ad-api.morefreegame.com`）收；`DOMAIN-KEYWORD,api.sobot.com` 是智齒客服，不是廣告，不收。
- `[Map Local]` 收直播帶貨、搜尋框填充詞（只對 `app.bilibili.com`）、影視頁活動投放、彈幕滿意度調查、開屏靜態素材；不收 `/x/mengqi/v*/resource`（用途不明）、`/x/web-interface/zone`、`/x/resource/ip`（IP 與地理位置查詢，不是廣告，擋了可能影響地區功能）。
- `[Script]` 另有 6 條把動態、播放頁、彈幕、評論、搜尋的 gRPC 回應交給 `bilibiliProtoA.js`：76 KB、14 行、最長一行 68,813 字元，裡面帶 `$httpClient`、`$persistentStore`、`$notification` 的輔助程式，打包過，**不採用**。所以動態頁與播放頁的廣告這個模組管不到。
- `[MITM]` 收 `app.bilibili.com`、`api.bilibili.com`、`api.live.bilibili.com`、`upos-sz-static.bilivideo.com`；`grpc.biliapi.net` 只有 proto 腳本用得到，不解密。

上游模組（`zhihu.sgmodule`，2026-05-11）重寫，差異：
- **不收 `USER-AGENT,AVOS*,REJECT`**：AVOS 是 LeanCloud SDK 的 UA，這條會擋到所有用 LeanCloud 的 App。
- **不收 `mqtt.zhihu.com`**（即時推送通道，擋了影響私訊與通知）、`appcloud2.in.zhihu.com`（內部設定，用途不明）、A/B 實驗設定的 reject（擋了功能會停在預設值）。
- **不收三個 IP 的 REJECT**：查 whois，`103.41.167.237` 是河北海鯨科技（HJ-HIDDOS），`118.89.204.198` 是騰訊雲，無法確認是知乎的 HTTPDNS；改由腳本關掉 App 的 HTTPDNS 達到同樣目的。
- `related-readings` 的正則上游拼成 `anwsers`，修正為 `answers`。
- 不收 `[Body Rewrite]`（`"recommend_queries":\{.+\}` 是貪婪比對，會吃到 JSON 結尾）；搜尋推薦詞是內容功能，不動。
- `[Map Local]` 只收廣告相關：開屏、首頁橫幅、回答與文章底部廣告卡（取自 fmz200 模組第 47 行，路徑在 `commercial_api` 下）、首頁彈窗、搜尋預設詞、廣告樣式（`ad-style-service/request`，取自 fmz200 第 73 行；上游 zirawell 寫成 `^https?://api.zhihu.com/ad` 沒有結尾，會把所有 `/ad…` 開頭的路徑都清空）、網頁版問答廣告卡。不收 `me/guides`（我的頁面項目）、`current_reading`、`related_queries`、評論區 `list-headers`、話題關聯、泡泡提示、小程式資源。
- fmz200 模組另有一條把 `link.zhihu.com/?target=` 302 轉向成 `http://…`（強制降成明文），**不收**，`link.zhihu.com` 也不解密。
- `[MITM]` 解密 `api.zhihu.com`、`www.zhihu.com`、`appcloud2.zhihu.com`、`zhuanlan.zhihu.com`、`zhstatic.zhihu.com`。`api` 與 `www` 也承載登入與帳號流量，腳本只動上面列的網址，但這兩個主機的流量都會經過 Surge 解密。

## 效果的限制

- 哔哩哔哩的動態頁、播放頁廣告走 gRPC／protobuf，可讀的腳本管不到。
- YouTube、X、Instagram、Facebook 都沒有可收的腳本。
- 兩支腳本依賴 App 目前的欄位名稱，App 改版後可能失效或漏掉新格式；上游有更新時（`tools/audit.py report` 不會追蹤腳本，要另外看 zirawell/R-Store 的提交）重新比對、重新審。

## 驗證

- `node --check` 兩支腳本。
- 假的 Surge 環境（`$httpClient`、`$persistentStore`、`$notification` 一碰就拋錯）餵合成回應 13 項：廣告卡拿掉、番劇與直播卡留下、「我的」頁面不再動、付費回答留下、`read`／`thread` 不被當成廣告、懸浮圖示真的刪掉、設定只關 HTTPDNS、非 JSON 原樣放行。
- 三個模組以 `surge-cli --check`（Surge Mac 6.9.1）驗證。
