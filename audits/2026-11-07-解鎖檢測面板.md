# 2026-11-07 解鎖檢測面板與流量面板修正

審核原則見 `AGENTS.md` 第 5 條。

## 採用：`modules/stream-check.js`（自己寫的）

| 項目 | 內容 |
|---|---|
| 類型 | Surge `type=generic` 面板腳本，不是 MitM 腳本，不攔截、不改寫任何請求 |
| 讀什麼 | 不讀參數 |
| 連到哪裡 | 只連被檢測的服務本身：`www.netflix.com`（1–2 次）、`www.youtube.com`、`api.openai.com`、`chatgpt.com`、`claude.ai`、`www.tiktok.com`，每次最多 7 個 GET。請求照設定檔規則分流，檢測的就是平常用的那條路 |
| 帶什麼 | 只有 User-Agent 與 Accept-Language；`auto-cookie` 關掉，不帶也不存 Cookie |
| 存什麼 | 什麼都不存：沒有 `$persistentStore`、沒有 `$notification`、沒有 `eval` 或動態產生程式碼 |
| 顯示什麼 | 每個服務一行：能不能用、出口地區；最後一行是更新時間 |
| 判斷依據 | Netflix：授權片 `/title/70143836` 的轉址讀地區，200 = 片庫完整，404 再看自製劇 `/title/81280792`，403 = IP 被擋。YouTube：`/premium` 的 `"GL"` 與「Premium is not available in your country」。ChatGPT：`compliance/cookie_requirements` 的 `unsupported_country`，地區看 `cdn-cgi/trace`。Claude：`cdn-cgi/trace` 的地區對照不提供服務的地區。TikTok：首頁轉到 `/about` = 不能用 |
| 沒放 | Disney+：地區要先向 Disney 註冊裝置才查得到，網頁本身看不出來 |

- 第 5 條「連往第三方主機就不採用」是防腳本把資料送出去；這支只連被檢測的服務自己，不送任何資料，屬於檢測本身。第 5 條已補上這個例外的說明。
- 用 Node 的測試替身驗證：真實服務跑一次（7 個請求、約 5 秒、五項都有結果）；模擬「只有自製劇」「地區不能訂」「不支援地區」「IP 被擋」「全部連不上」都顯示對的文字與樣式；連到的主機只有上面六個。
